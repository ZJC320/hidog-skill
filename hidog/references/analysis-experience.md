# 跨文库分析经验

> 适用于 Cas9、PE、dualPE、扩增子等各类 HiDOG 文库；不针对某个基因或某个批次。
> 这里记录的是**通用判断规则**；具体参数、输入格式和报告交付以 [使用说明](usage.md)、[输入规范](input-format.md)、[报告口径](reporting.md) 为准。

---

## 0. 三条最高优先级

1. **先证明“文库是什么、参考对不对”，再谈编辑效率。** 文件名、样品表、历史命名都只是假设；内容验证优先。
2. **异常先做小规模诊断，不要用参数硬压。** 每端 20 万 reads 的构成验证、全长基因 mapping、单倍型位点检查，通常十几分钟就能定位问题。
3. **报告必须给分布和主等位，不只给中位数/均值。** EF/PE 的双峰分布、EF≈100% 饱和、某一亚基因组缺失，都会被单一中位数掩盖。

---

## 1. 前置验证（每次分析必做）

### 1.1 数据完整性
- 核对 FASTQ 的校验值/压缩完整性/reads 数；不通过不进入分析。
- 数据包中缺失的文件（如测序报告）单独注明，不要默认为数据完整。

### 1.2 文库构成验证（主分析前）
- 每库每端抽样约 20 万 reads，比对**候选参考全集**（目标基因 + 可能的污染/错标基因），按参考名统计命中。
- 目的：确认文件内容与命名/样品表一致；发现互换、错标、污染、混合池。
- **文件名不可信**：实际遇到过文库名与内容不符、亚基因组标错、不同项目混标等情况；构成验证是可靠的入口检查。
- 混合池（一个文库含多个基因）要先确认基因集合，不能假设“一个文库一个基因”。

### 1.3 参考序列 QC
- **guide 精确匹配 + PAM**：逐条参考检查 guide 是否 exact、PAM 是否符合编辑工具要求（Cas9 通常 NGG）；非 NGG 的亚基因组不能按“可切割”解读。
- **header 命名一致**：参考与 guide 的命名规则要能一一对应；不要带 `_CBE` 等后缀，否则可能触发按文件顺序的静默错配。
- **A/B/D 可区分性**：若两个亚基因组扩增区段几乎相同，强行 A/B/D 分析会把 reads 全判给其中一个；应改用区分度最高的单参考 + 关闭同源分析。
- **与全长基因的一致性**：新 amplicon 参考若与全长基因无精确匹配，先怀疑参考/扩增子边界/单倍型，不要直接开跑。
- **多 guide**：确认每个 guide 在各亚基因组的切点位置；多 guide 基因使用对应多 guide 模式，并检查 per-guide 列。

### 1.4 异常入口规则
- **BWA qnames 正常但 hard assigned≈0** → 优先做全长基因 mapping，确认 reads 真实来自哪个基因/区间；必要时按 reads 覆盖区间从全长基因提取参考。
- **BWA qnames <100** → 数据量/拆分/barcode/污染问题，不是参考问题。
- **整库 hard≈0 且 qnames 正常** → 不要反复调 `--min-identity-score` 等参数；先查参考与内容是否匹配。

## 2. 分析模式选择（按生物学，不按习惯）

| 情况 | 推荐模式 |
|---|---|
| 单拷贝/单序列基因 | 单参考 + 关闭同源分析 |
| 多拷贝且 A/B/D 可区分 | A/B/D 参考 + 同源分析 |
| 两个亚基因组几乎不可区分 | 选区分度最高的单参考 + 关闭同源分析 |
| 一个参考对应多个 guide | 允许一个参考绑定多个 guide |
| 多基因混合池 | 按池内基因集合生成合并参考 + 合并 guide；不要按单基因硬拆 |
| PE / dualPE / 扩增子 | 用对应编辑工具 + pegRNA/scaffold/扩增子参数；不要用 Cas9 模式套 PE 数据 |

补充：
- 单序列参考不使用“按目标基因自动找 A/B/D”的入口；用 per-gene 参考。
- 混合池不要全局关闭同源分析；按 group 处理。
- 混合池的 barcode 可能按基因分区块，也可能同一样品共扩增；先由数据判断，再解读“无数据”。

## 3. 深度与分配 QC（per sample + per subgenome）

### 3.1 两类“没数据”要分开
- **无数据**：该基因各亚基因组 BWA qnames <100。
- **低测序深度**：有数据，但某亚基因组展示 reads <1000。
- 报告中必须分列，不能混成一个“低深度”数字。

### 3.2 深度阈值
- hard assigned ≥1000/样品/亚基因组：可做定性判断；
- ≥2000：较稳定；
- ≥5000：完全稳定（抽样实验结论）。
- 先看**每样品每亚基因组**，再看库合计；库合计高不代表每个样品都够。

### 3.3 分配率异常的判读

| 现象 | 更可能的原因 |
|---|---|
| BWA qnames 高、hard 低 | 参考不匹配 / 同源竞争 / 分配窗口问题 |
| BWA qnames 低 | 数据量、barcode 拆分、污染 |
| 某一亚基因组 hard=0，其他正常 | 该亚基因组模板缺失/引物不匹配（不是“未编辑”） |
| 混合池某基因大量“无数据” | 该基因在别的 barcode 区块（正常） |
| 全库 hard≈0、qnames 正常 | 映射/参考错误，先做全长诊断 |

### 3.4 “无数据”孔不一定是空孔
- 原始 reads 可能来自污染/其他基因；报告“目标基因无数据”时，附上原始 reads 量与污染比例，避免把“空孔”与“错标”混为一谈。

## 4. EF / PE 结果解读

### 4.1 EF 的定义边界
- Cas9 `Editing frequency` 统计窗口内的**任何变异**，不等于“精确预期编辑”。
- PE 报告应同时看 **Prime editing efficiency** 与 **Prime editing precision**；EF 高不等于精确编辑。
- 固定编辑叠加测序错误会让 EF≈100%；此时应报告“携带主导切点变异的比例”和“精确主等位占比”。

### 4.2 必看分布与主等位
- 逐样品看 EF 分布；**双峰分布**（一部分编辑、一部分 WT）时，中位数会严重误导。
- 主等位表是判断“真编辑 vs 参考错配”的关键：
  - 主等位是预期编辑 → 可信；
  - 主等位是固定非预期变异 → 先怀疑参考/样品单倍型；
  - 主等位是 WT、EF 却很高 → 检查是否把其他窗口/骨架算入。
- EF≈0 不一定是“没编辑”：可能是 guide PAM 非 NGG、某一亚基因组不可切割、或参考不匹配导致 reads 未分配。

### 4.3 参考错配的两种假象
- **假阳性**：参考与样品在某位点固定不同，被当作 100% 编辑；
- **假阴性**：预期编辑产物恰好等于其他亚基因组的天然碱基，被同源过滤隐形。
- 处理：核对参考组内一致性；检查分析上下文的 informative sites 是否覆盖预期编辑位点；必要时用样品自身序列重建参考。

## 5. 亚基因组平衡（D_ABD / Balance Score）

- D_ABD 与 Balance Score 是 **effect-size/QC 指标**，不做卡方检验；深度高时微小偏差也会“显著”，不要用 P 值判平衡。
- 四级分类 cutoff（0.80/0.60/0.40）是项目默认 QC 参数，不是文献统计学阈值。
- **某一亚基因组 hard=0 时**（模板缺失/引物不匹配），不要判为“Severe imbalance”；应标记为“该亚基因组缺失，平衡不适用”。
- 先排除技术性缺失，再谈生物学偏倚。

---

## 6. 资源与运行通用规则

### 6.1 Pilot 要选“最复杂”的库
- 多基因混合池（多基因 × 多参考 × 多样品）比单基因库更容易在 Summary 阶段 OOM；pilot 必须覆盖最复杂类型。
- 多基因混合池建议使用更充足的核数/内存，并降低 summary 并行 worker 数；不要用最小资源试最复杂池。
- PE 大文库按实际资源增加核数；worker 数要匹配内存预算。

### 6.2 不要按“没有新输出”判死锁
- BWA 后的 assignment 阶段可能数小时不写文件；日志未生成、终端无输出都不是死锁证据。
- 可靠指标是**一段时间窗口内 CPU time 完全不增长**；确认后再终止并用断点续跑。
- 长任务不要因为暂时没有新输出就重启。

### 6.3 提交与文件安全
- 含空格的路径全部加引号；提交脚本使用 UTF-8。
- 批量提交逐条执行并容错，不用一次性 shell 批量导致单个失败全部跳过。
- 运行目录与中间文件独立；失败时保留排错文件，不提前清理。

## 7. 交付与记录（每批固定动作）

1. **每库/每目标报告**：程序版本、参数、参考/guide；无数据清单；低深度清单（亚基因组分列、<1000 高亮）；A/B/D 平衡；QC；EF/PE plot。
2. **数据质量评估**：各库/基因扩增效果、无数据/低深度比例、平衡分级、重点异常与解读。
3. **clean-result**：按 [报告口径](reporting.md) 只交付 `*_summary_by_reference/`、`html_reports/`、`plots/`、`qc_reports/`，验证后清理本次中间文件。
4. **运行记录**：文库、程序版本、参数、参考/guide、运行时间、失败样本、限制与结果位置。
5. **版本核对**：分析前确认程序版本与校验值；不要用未验收开发版替代固定版本。

---

## 8. 版本选择（通用原则）

- **按编辑工具选已验收版本，不按“最新”选**：
  - Cas9 / BE / Cpf1：优先项目验证过的稳定版本；
  - PE / dualPE：关注 PE 专项修复（如单 PE 微小 scaffold 掺入识别）；
  - 扩增子：使用对应编辑工具模式。
- 仓库 HEAD 可能在特性分支上，包含未验收修复；使用前确认该修复是否适用于当前工具，并做 pilot 对比。
- 任何版本切换都要记录版本号/校验值、差异点、pilot 对比结论。

---

## 9. 最小检查清单

- [ ] FASTQ 校验值/压缩完整性/reads 数通过
- [ ] 构成验证完成（每端约 20 万 reads，候选参考全集）
- [ ] 每个参考的 guide exact + PAM 正确
- [ ] header 命名一致，无后缀陷阱
- [ ] A/B/D 可区分性评估；不可区分时改单参考
- [ ] 单/多拷贝、单/多 guide、混合池模式选择正确
- [ ] 最复杂库已做 pilot（核数/内存/worker 足够）
- [ ] 深度按样品×亚基因组评估（≥1000 可靠、≥2000 稳）
- [ ] EF/PE 看分布与主等位，不只看中位数
- [ ] 平衡分析排除“亚基因组缺失”造成的假 Severe
- [ ] 报告/质量评估/clean-result/运行记录齐全
- [ ] 无异常退出、无 OOM、无 core dump

## 10. 异常决策树（速查）

```text
文库无数据
├─ BWA qnames <100 → 查数据量/barcode 拆分/污染/错标
└─ BWA qnames 正常但 hard≈0
   ├─ 全长 mapping 命中其他基因 → 映射表错误，按真实区间提取参考
   ├─ 全长 mapping 命中目标基因但区间不同 → amplicon 边界/引物不同，按覆盖区间重建参考
   └─ 无明确命中 → 污染/非目标文库，报告并排除

某亚基因组 hard=0
├─ 该亚基因组模板缺失/引物不匹配 → 报告缺失，不做平衡结论
└─ guide PAM 非 NGG → 该亚基因组不可切割，EF 低是预期

EF≈100%
├─ 主等位=预期编辑 → 可信，但仍报告精确主等位占比
├─ 主等位=固定非预期变异 → 参考/单倍型错配，先核对参考
└─ EF 高但主等位 WT → 检查窗口/骨架/分类逻辑

EF≈0
├─ 主等位 WT 且深度足够 → 真实未编辑
├─ 某亚基因组 PAM 非 NGG → guide 限制
└─ hard≈0 → 参考/分配问题，不是“未编辑”
```
